topic: YS Data Agent 统一 LLM Provider 管理
updated: 2026-09-01T20:23
---

- (decision) 以 liter-llm 统一实现 LLM Provider 接入层，替换现有自定义 OpenAI-compatible Provider，以降低多 Provider 适配与维护成本。
- (decision) 目标用户是需要在产品中配置和切换不同 LLM Provider 的用户。
- (decision) 目标体验是用户可通过 TUI 查看、配置并切换 Provider、模型及相关参数。
- (decision) 本次不重构与 Provider 管理无关的 LLM 调用链路。
- (decision) 本次不引入 liter-llm 支持范围以外的自定义 Provider 协议。
- (event) 上游 Product Brief 已 approved，Addendum 已 ready-for-handoff；两者将作为 PRD 输入进行提取与最终对账。
- (decision) 本次需求属于现有 YS 产品的 TUI 优化想法，重点是 Provider 管理体验，而非独立新产品。
- (override) 纠正先前范围误读：本 PRD 的主体是 YS Data Agent 统一 LLM Provider 管理；TUI 只是相关交互界面之一，不是产品目标或需求范围的主轴。
- (decision) 用户选择 Fast path：集中补齐剩余关键缺口后直接起草完整 PRD，推断项使用 [ASSUMPTION] 标记。
- (decision) Provider Catalog 以 liter-llm 开箱支持的 165 个 Provider 为产品范围，使用 provider/model 前缀路由，不另设 YS 厂商白名单。
- (assumption) 目录支持不等于运行兼容；所选模型需通过 YS 必需能力校验后才能激活，因为 Provider 级 Chat 标记不能证明模型级工具调用契约。
- (assumption) 采用多个具名 Provider Profile、一个活动 Profile 的配置模型；每个 Profile 隔离 Provider、模型、凭证引用和参数。
- (assumption) TUI 只保存凭证引用而不持久化明文密钥；具体密钥载体由后续设计确定。
- (assumption) Provider 切换仅影响之后启动的 Task/Run，进行中的 Run 保留启动快照，且系统不做静默自动回退。
- (assumption) 现有 YSDA_LLM_BASE_URL、YSDA_LLM_API_KEY、YSDA_LLM_MODEL 自动映射为迁移 Profile，以保持升级兼容。
- (assumption) 首期统一参数为模型 ID、temperature、max tokens、timeout 和 retry；额外参数仅在 liter-llm 与目标 Provider 明确支持时提供。
- (event) 已完成 approved Product Brief、ready-for-handoff Addendum 的独立提取及 liter-llm 官方资料研究；研究确认 165 Provider 注册表与 provider/model 路由，同时发现 Provider 级能力、凭证隔离和模型枚举边界。
- (override) 覆盖此前 165 Provider MVP 范围：首期仅实现 chatgpt/、opencode-go/、opencode/、deepseek/、xai/、zai/、openrouter/、minimax/、anthropic/ 共 9 个 Provider；其余 liter-llm Provider 延后。
- (assumption) 用户所称 ChatGPT 按 liter-llm 的 ChatGPT Subscription（chatgpt/）解释，不等同于 OpenAI API（openai/）；如需 OpenAI API 将另行纳入。
- (decision) ChatGPT 目标 Provider 正式确认为 ChatGPT Subscription（chatgpt/），不包含 OpenAI API（openai/）。
- (override) 覆盖凭证引用假设：用户直接在 TUI 粘贴 API Key，YS 必须在本地安全持久化；用户无需配置环境变量名称。
- (decision) Provider Profile 对用户呈现 Provider Credential（通常为 API Key）；明文仅在输入时短暂存在，保存后不得重新显示或进入普通配置、日志、Telemetry、Run 事件或 Artifact。
- (override) 覆盖所有迁移与发布兼容假设：YS 当前仍在开发阶段且没有存量用户，本期不做旧 YSDA_LLM_* 导入、兼容窗口、用户迁移、双实现回退或迁移指标。
- (decision) 直接以 liter-llm 替换自有 OpenAI-compatible Provider；只保留开发阶段必要的现有模型调用契约回归与 9 个目标 Provider 验收。
- (change) PRD 中的目标用户改为未来预期用户，不能暗示已有部署、升级用户或迁移场景。
- (event) 用户批准 PRD Fast path 初稿，进入最终化流程。
- (change) 依据 Product Brief 对账，明确 Provider 功能指标从属于 Query Pilot 的覆盖率、自助完成率与严重静默错误门槛，不能以 Provider 指标替代产品价值验证。
- (change) 依据 Product Brief 对账，Provider Profile 激活与切换不得扩大批准的数据外发或成本边界。
- (change) 依据 Product Brief 对账，Provider 技术操作用户不替代业务使用者、Data Steward 或 Accountable Data Owner 的产品级治理职责。
- (change) Reviewer Gate autofix：首期 9 个目标 Provider 使用 liter-llm 固定端点，不允许用户覆盖 Base URL，以避免 Provider Credential 发往非预期 origin。
- (change) Reviewer Gate autofix：本地安全凭证存储不可用时失败关闭，不得降级为明文存储；create/replace/delete 必须原子且可验证。
- (change) Reviewer Gate autofix：Provider Credential 隔离验收覆盖并发 Run、校验、重试和失败路径，禁止跨 Profile Client 或认证状态复用。
- (change) Reviewer Gate autofix：任一目标 Provider 未通过真实能力验收时不得宣称 9/9 完成；移除或降级目标 Provider 必须重新批准 PRD 范围。
- (override) 用户明确拒绝移除 chatgpt/：ChatGPT Subscription 必须保留为首期 9 个强制目标 Provider，不得降级、延期或替换为 openai/。
- (decision) ChatGPT Subscription 使用独立 OAuth 登录流程；其余 8 个目标 Provider 继续由用户在 TUI 粘贴 API Key。
- (decision) ChatGPT OAuth access/refresh token 由本地安全凭证存储保护，并支持连接状态、刷新、过期、撤销与登出生命周期。
- (decision) cc-sdd design 批准前必须锁定真正实现 chatgpt/ 路由与 OAuth 的 liter-llm 版本；若无可用版本则实施保持 BLOCK，禁止在 YS 内自建协议绕过。
- (override) 用户确认当前 liter-llm 已支持 ChatGPT Subscription OAuth；覆盖 Reviewer Gate 基于固定提交提出的依赖 BLOCK，不再把 chatgpt/ 作为外部实现阻塞。
- (change) PRD 保留 ChatGPT Subscription OAuth 产品流程与验收，但删除固定提交缺失结论、design/implementation BLOCK 和相关依赖风险措辞。
- (decision) Fast path 默认项收口：MVP 支持多个本机应用级 Provider Profile，任一时刻只有一个全局活动 Profile。
- (decision) Fast path 默认项收口：首期通用参数固定为模型 ID、temperature、max tokens、timeout 和 retry。
- (decision) Fast path 默认项收口：Provider 切换只影响之后启动的 Task/Run，进行中 Run 保留启动快照。
- (decision) Fast path 默认项收口：本期不提供自动回退、负载均衡或隐式路由。
- (decision) 目标 Provider 的代表性模型与测试凭证由项目维护者负责，在 Provider 标记 Supported 前提供；Provider Catalog 在每次 liter-llm 版本升级时复核。
- (event) PRD finalized
