# v0.2 Task 13 Focused TUI Design

## Status

Approved in conversation on 2026-08-31. This document refines the TUI portion of `docs/superpowers/plans/2026-08-15-v0.2-task-13-step-by-step.md` and supersedes the visual layout in `docs/superpowers/specs/2026-08-29-tui-terminal-mockup-design.md`. The earlier safety semantics remain valid.

## Objective

Build a concise, answer-first Ratatui interface for YS Data Agent. The interface should feel like a native terminal workbench, keep runtime authority behind `AgentServiceApi`, and reveal secondary information only when the operator asks for it.

The design selectively adopts interaction patterns from VTCode's TUI implementation. It does not depend on `vtcode-ui`, copy VTCode's business model, or reuse VTCode's color configuration.

## Locked product decisions

- Running `ysda` without a subcommand opens the TUI.
- The welcome view is minimal: safe workspace status, one short prompt, and Composer.
- After submission, the main region becomes a full-width answer transcript.
- There is no persistent right sidebar and no `Recent work` section.
- The assistant role label is `Ys-da`.
- The default answer shows only the conclusion, the most important one or two values, and at most one short explanatory sentence.
- Query parameters, checks, Artifacts, SQL, metrics, and diagnostics are hidden until requested.
- Typing `/` opens a full-width command palette in the bottom region. While open, it replaces Composer rather than creating a second input.
- `/quit` and Ctrl-C detach the TUI without cancelling a Run. `/cancel RUN_ID` remains the only cancellation action.
- The approved default visual direction uses a deep navy background, blue dividers and labels, grey-white body text, and cyan status accents.
- Operators may choose a preset theme or configure every semantic color.

## Screen structure

### Welcome

The welcome view has three regions:

1. A single-line header with `Agent`, safe Workspace identity, Doctor readiness, model label, connection label, and read-only permission.
2. An otherwise empty full-width content region containing one short invitation to ask a governed data question.
3. Composer plus a one-line footer.

It does not show recent Tasks, internal IDs, example cards, metrics, or a sidebar.

### Answer

After a query starts, the content region becomes a transcript. The default completed answer follows this order:

1. The user's question.
2. `Ys-da` plus a short state such as `completed · 1.7s`.
3. One-sentence conclusion.
4. Up to two decision-useful values.
5. An optional one-sentence explanation.

Detailed tables, SQL, safety checks, query parameters, Artifact metadata, and runtime identifiers are not rendered in the default view.

### Clarification

When the durable Run Snapshot is `WaitingForInput`, the transcript displays the clarification question and optional recommended default. The next non-command submission answers the same Run. Commands remain available while clarification is pending.

### Repair

Doctor blockers replace the main content with concise repair instructions. Secret values, dependency `Debug` output, database URLs, and API keys never enter display state.

## Slash-command palette

Typing `/` at the start of Composer opens a bottom-docked palette inspired by VTCode's slash palette.

The palette:

- occupies the full terminal width;
- replaces the base Composer and owns the only visible cursor;
- shows a search field above results;
- filters by command name and description;
- uses a fixed maximum of six visible command rows;
- supports Up, Down, PageUp, PageDown, Enter, Tab, mouse selection when enabled, and Esc;
- keeps the selected row visible while results scroll;
- disappears when the command token no longer begins with `/` or no result matches;
- restores the preserved draft when dismissed.

Enter immediately submits a complete no-argument command. For a command requiring arguments, Enter inserts the selected command plus a trailing space into Composer and closes the palette.

### Information commands

These commands temporarily replace the transcript body with a focused detail view. Esc returns to the previous answer without modifying durable runtime state.

| Command | Content |
|---|---|
| `/metrics` | Key metrics associated with the current verified answer. |
| `/query` | Time range, governed metric, comparison, and query phase summary. |
| `/checks` | Read-only, policy, freshness, and governance results. |
| `/artifact [ARTIFACT_ID]` | Current primary Artifact when omitted, or a specific Artifact when provided. |
| `/sql` | Persisted executed SQL for the current answer; never reruns a query. |
| `/details` | Session, Task, Run, Step, and Query phase diagnostics. |

`/export ARTIFACT_ID FORMAT`, `/doctor`, `/new`, `/tasks`, `/task`, `/resume`, `/cancel`, `/model`, `/connections`, `/help`, and `/quit` retain the semantics in the Task 13 plan.

If an information command requires a focused completed Run and none exists, the UI shows a short warning and leaves the current view unchanged.

## Theme system

YSDA owns its theme model. VTCode's theme registry, color-mixing functions, and defaults are explicitly out of scope.

### Semantic tokens

`YsdaTheme` contains exactly these configurable colors:

- `background`
- `surface`
- `header`
- `border`
- `text`
- `muted`
- `accent`
- `success`
- `warning`
- `error`

Renderers consume semantic tokens and contain no literal colors.

### Default theme

The default `deep-navy` preset uses the approved reference direction:

```toml
background = "#071423"
surface = "#101D2E"
header = "#202A38"
border = "#224B79"
text = "#C5CAD3"
muted = "#7E8999"
accent = "#4389E6"
success = "#66BAD9"
warning = "#E0B866"
error = "#E06C75"
```

These are the initial locked values for the `deep-navy` preset. Any later change requires a user-visible theme review. They are not derived from VTCode.

### Presets and customization

`/theme` opens the same bottom-docked selection surface as other palettes. Up and Down preview a theme without persisting it. Enter confirms and saves; Esc restores the theme active before the selector opened.

The first release provides a small preset registry, including `deep-navy`, `terminal`, `nord`, and `gruvbox`. The registry is data, not branching renderer logic.

Operators may customize individual tokens:

```text
/theme set accent #4389E6
/theme set background #071423
/theme reset
```

The equivalent persistent file is `.ysda/ui.toml`:

```toml
theme = "custom"

[colors]
background = "#071423"
surface = "#101D2E"
header = "#202A38"
border = "#224B79"
text = "#C5CAD3"
muted = "#7E8999"
accent = "#4389E6"
success = "#66BAD9"
warning = "#E0B866"
error = "#E06C75"
```

Accepted values are `#RRGGBB`, ANSI named colors, `ansi:N` for 0–255, and `default`. Invalid input leaves the last valid theme active and produces the stable code `invalid_theme_color`. `NO_COLOR` disables decorative colors while preserving labels and symbols.

The preference file is local UI state, contains no secrets, and is written owner-only. `TuiApp` does not perform filesystem I/O. The outer application host loads preferences during bootstrap and persists an approved update emitted by the controller.

## Component design

### `TuiApp`

Pure display state only:

- current view mode;
- safe header labels;
- typed transcript items;
- focused detail view;
- Doctor report;
- Composer state;
- slash palette state;
- active and preview themes;
- scroll state and quit flag.

It contains no `AgentServiceApi`, store, Connector, model provider, or filesystem handle.

### `TuiController`

Owns service-facing identity and maps typed actions to `AgentServiceApi`. It retains `CommandId` across an uncertain response, owns focused Session/Task/Run identity, and reloads the durable Snapshot after service notifications.

Theme and palette changes are UI-local actions. Persisting preferences is emitted to the application host and does not pass through the query runtime.

### `ComposerState`

Wraps `ratatui-textarea::TextArea` behind a small YSDA interface. Adopt only the VTCode-proven capabilities needed here:

- UTF-8-safe cursor movement and editing;
- multiline paste;
- undo and redo;
- submission history with draft restoration;
- a single rendered cursor.

Images, Vim mode, file references, clipboard attachments, and external-editor support are out of scope.

### `SlashPalette`

A pure model containing command metadata, normalized filter text, selected index, scroll offset, and visible row count. Parsing and command execution remain separate. Tests can exercise ranking and navigation without a terminal.

### `TransientView`

YSDA uses one active transient view rather than VTCode's general stacked surface host:

```text
None
SlashPalette
ThemePicker
Detail(Metrics | Query | Checks | Artifact | Sql | Diagnostics)
Help
Repair
```

Only one transient view owns input at a time. Esc closes the active transient and returns to the preserved transcript or clarification state.

### `ThemeRegistry` and preference host

`ThemeRegistry` validates preset names and semantic tokens. The application host owns `.ysda/ui.toml` I/O, uses private file permissions, and sends validated preferences into `TuiApp`.

## Responsive behavior

YSDA adopts the useful part of VTCode's responsive layout concept without adopting its sidebar:

- `Compact`: width below 80 or height below 20. Hide nonessential header labels and footer hints; omit decorative borders.
- `Standard`: the normal full-width transcript and Composer.
- `Wide`: increases readable answer width and margins but does not introduce a sidebar.

All arithmetic uses saturating operations. Rendering a 60x12 terminal may wrap or truncate content but must not panic.

## Event loop and redraw

Keep Tokio and Crossterm separation from the Task 13 plan, with these selective VTCode improvements:

- mark display state dirty after meaningful input, service events, resize, animation, or view changes;
- draw only when dirty;
- use a faster active tick and slower idle tick rather than a fixed 100 ms redraw forever;
- bias `tokio::select!` toward terminal input so service-event bursts do not make typing lag;
- process a bounded number of queued service and terminal events per turn;
- coalesce scroll events only when no palette owns navigation;
- treat live service events as hints and reload the authoritative durable Snapshot.

The v0.2 target is 30 Hz while actively editing or displaying a spinner and 4 Hz while idle. No animation may change durable state.

## Terminal lifecycle

Replace the minimal raw-mode guard with a tracked, idempotent terminal mode guard:

- raw mode;
- alternate screen;
- bracketed paste;
- cursor visibility and shape;
- optional focus events;
- optional mouse capture only if mouse interaction is enabled.

Every successfully enabled mode is recorded separately. Normal return, `?`, Ctrl-C, and panic restoration disable only modes that were enabled. Restoration is safe to call more than once. `/quit` and Ctrl-C restore the terminal but do not call `cancel_run`.

## Selective VTCode integration boundary

| Adopt the pattern | Do not adopt |
|---|---|
| Bottom-docked slash palette that replaces Composer | VTCode command catalog or coding-agent commands |
| TextArea-backed UTF-8 editor and history | Attachments, Vim, file palette, external editor |
| Dirty redraw, adaptive ticks, input priority | VTCode's entire runner abstraction |
| Bounded event draining and safe scroll coalescing | PTY and tool-output event models |
| Tracked and idempotent terminal restoration | VTCode panic-report presentation |
| Responsive layout modes | Persistent or automatic sidebar |
| Semantic style access from renderers | VTCode theme registry and color mixing |

No YSDA crate depends on `vtcode-ui`.

### VTCode reference files

The implementation plan may consult these files for behavior and test ideas without copying VTCode-specific state or configuration:

- `crates/codegen/vtcode-ui/src/tui/core_tui/app/session/slash.rs` — bottom-docked slash rendering, filtering, navigation, completion, and dismissal.
- `crates/codegen/vtcode-ui/src/tui/core_tui/app/session/slash_palette.rs` — pure suggestion and selection state.
- `crates/codegen/vtcode-ui/src/tui/core_tui/session/tests/slash_palette.rs` — single-input ownership, fixed panel height, and full-width panel tests.
- `crates/codegen/vtcode-ui/src/tui/core_tui/session/input_manager.rs` — `TextArea` wrapper, Unicode editing, undo/redo, history, and draft restoration.
- `crates/codegen/vtcode-ui/src/tui/core_tui/app/session/layout.rs` — bottom-panel height resolution.
- `crates/codegen/vtcode-ui/src/tui/core_tui/runner/drive.rs` and `runner/events.rs` — dirty redraw, bounded draining, input priority, adaptive tick rate, and scroll coalescing.
- `crates/codegen/vtcode-ui/src/tui/core_tui/runner/terminal_modes.rs` — tracked terminal modes and idempotent restoration.
- `crates/codegen/vtcode-ui/src/tui/core_tui/session/styling.rs` — semantic style access only; its concrete theme values and color-mixing behavior are excluded.

## Error handling and safety

- Terminal text is sanitized before rendering.
- Raw model and Tool payloads do not enter the default transcript.
- Doctor reports contain stable codes and curated repairs only.
- Theme errors preserve the last valid theme.
- Detail commands read persisted Runtime state and Artifacts; `/sql` and `/artifact` never execute a query.
- Restricted Artifact preview and export remain governed by `ArtifactAccessContext` and export policy.
- Unknown slash commands remain UI errors and are never forwarded to the model.

## Verification

### Pure tests

- Slash parsing, prefix extraction, fuzzy filtering, selection, scroll bounds, and argument completion.
- Composer UTF-8 editing, multiline paste, undo/redo, history, and draft restoration.
- Theme token parsing, preset selection, custom overrides, reset, invalid-value rollback, and `NO_COLOR`.
- Transient focus transitions and Esc restoration.
- Compact, Standard, and Wide layout resolution.

### Ratatui `TestBackend` tests

- Welcome view contains no recent-work section or internal IDs.
- Answer view is full width and contains no right sidebar.
- The role label is `Ys-da`.
- Default answer remains concise.
- Slash palette hides Composer and renders only one cursor/search field.
- Palette height stays stable for short and long result sets.
- `/metrics`, `/query`, `/checks`, `/artifact`, `/sql`, and `/details` render focused views and return with Esc.
- Theme preview changes semantic styles and Esc restores the previous theme.
- 60x12, 80x20, 100x28, and 150x40 rendering does not panic.

### Runtime and manual tests

- Terminal restoration works after normal exit, error, Ctrl-C, and panic unwinding.
- Typing remains responsive during bursts of durable Run Events.
- `/quit` does not cancel work.
- Reopening the app restores the selected or custom theme.
- Invalid or partially written `.ysda/ui.toml` falls back to the last valid/default theme with a safe warning.
- Doctor, Artifact access, export denial, command replay, and same-Run clarification tests from Task 13 remain green.

## Completion criteria

- The approved full-width, no-sidebar visual design is represented by deterministic tests.
- Secondary information is accessible through slash commands and absent from the default answer.
- Operators can select preset themes and configure every semantic color.
- The default theme matches the approved deep-navy reference direction without using VTCode theme configuration.
- Only the explicitly selected VTCode interaction patterns are reimplemented.
- Runtime authority and safety boundaries from the original Task 13 plan remain unchanged.
